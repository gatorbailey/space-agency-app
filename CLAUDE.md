# Space Agency — Project Brief

## Concept
A strategy/management sim where the player is the **administrator** of a
Cold War-era space program (starting 1960), not a pilot. Goal: put a human
on Mars. Styled after *For All Mankind* — real historical stakes and
pacing, but generic/fictionalized names for tech, programs, rival nations,
and anything legally or politically sensitive.

## Platform & Stack
- **iOS app**, built as a web app wrapped via **Capacitor** (no Swift
  required). Low-cost, Claude-Code-friendly stack.
- **React + TypeScript + Tailwind**, Vite build tooling.
- **Architecture split (critical):**
  - **Simulation Core** — pure TypeScript, zero UI dependencies. Owns the
    clock/turn engine, resource ledger, event/card resolver, save state.
    Fully unit-testable in isolation.
  - **Content Data** — cards, tech tree nodes, mission scripts as
    JSON/TS data objects. Content authors (including Claude) should be
    able to add content without touching engine code.
  - **UI & Presentation** — React screens, map, cards. Reads from and
    dispatches actions to the Simulation Core; has no game logic of its
    own.
  - **Save & Persistence** — local-only for MVP; cloud sync added in
    Phase 2.
  - **Platform Shell** — Capacitor wrapper for iOS distribution.

## Time Model
Originally scoped as discrete daily turns; **now settled on a continuous
flowing clock** (SimCity-style, not Civilization-style) with adjustable
speed (paused/normal/fast/faster). Internally still resolves in fixed
daily ticks — the player just isn't clicking "End Day."

- **Status menu, not hard-pause, is the default interrupt mechanism.**
  A persistent menu item shows a badge when a site has a significant
  update, decision, event, or action item. Clicking it opens a list of
  flagged items, tagged by site and severity, drilling into the actual
  decision screen.
- **Exception:** a scheduled launch reaching its go/no-go window is a
  **hard pause** — this is the one moment time pressure must be real.
- Every event/card the Simulation Core generates should carry a
  `severity: 'flag' | 'pause'` field from day one, even though MVP will
  only ever use `pause` — this avoids a Phase 2 retrofit.

## Core Resource Web
- **Sentiment** — driven by mission success, press circuit, astronaut
  appearances, tech reveals. Sets the ceiling on the next budget
  appropriation. The one resource everything else ripples back into.
- **Budget/Funds** — hard currency, granted in appropriation cycles
  sized by current Sentiment.
- **Intelligence** — funded from budget; reduces risk/uncertainty
  (weather, rival moves, sabotage) and is the primary way the player
  scouts the rival program. (Phase 2+)
- **Raw Materials** — regionally sourced, tied to distributed sites;
  real supply-chain mechanic (e.g. barge/rail shipments between sites
  that can be delayed by weather).
- **R&D** — generated by labs/technical labor; spent on the tech tree.
- **Labor** — split into **Technical** (engineers/scientists — feed R&D
  and mission readiness, scarce/poachable) and **Operations**
  (technicians/ground crew — feed construction/launch prep, bulk
  workforce pool). (Full split is Phase 2+; MVP uses a generic
  "crew readiness" stat.)

Loop: missions/construction consume resources → outcomes swing
Sentiment → Sentiment sets next Budget → Budget funds the other
resources → repeat.

**Passive/idle accrual:** Materials (and base R&D) accrue passively per
facility, capped by storage, collected by the player — this is the
daily-engagement hook. Consecutive-engagement streaks grant small
Sentiment/Intel bonuses framed as "administration continuity."

## Sites (Distributed Network Model)
Not a single SimCity-style base — a network of real-style sites (Cape
Canaveral, Vandenberg, Houston, Marshall Islands, offshore platform,
etc.), each with distinct advantages/disadvantages (weather patterns,
logistics, geopolitics, cost). **All sites can eventually reach peak
capability — site choice affects *pace*, not a hard ceiling.**

Buildings mimic real NASA infrastructure: pads, VAB/assembly, fueling
depots, crawler-transporter, mission control, training center, R&D lab.

## Site Security
Four distinct threat types, each pulling against different mitigations
(not one generic "security %" bar):
- **Wandering public/trespassers** — low stakes, high frequency, fixed
  by fencing/patrols; occasional PR upside or downside.
- **Environmentalists** — a negotiated pressure, not a neutralized
  threat (PR campaign, genuine mitigation spend, or ongoing Sentiment
  penalty).
- **Spies** — mitigated by Intel investment; undetected leaks show up
  later as suspiciously similar rival tech.
- **Saboteurs** — highest stakes, lowest frequency, should be
  foreshadowed by Intel rather than a total surprise.

## Site Tours
- **Public tours** — small reliable Sentiment trickle, low mishap
  chance/severity.
- **VIP tours** — bigger Sentiment payoff (possibly the only way to get
  a mid-cycle emergency budget bump), higher mishap chance/severity
  scaled to who's touring. Flavor mishaps (e.g. spilled coffee on
  expensive equipment) are a deliberate tone-setter — the game has a
  sense of humor about bureaucratic reality.

## Launch Planning
A set of trade-off sliders resolved into a single risk read before
commit:
- **Payload type** — commercial (Funds, low Sentiment), research (R&D,
  modest broad Sentiment), military (moves geopolitical tension needle,
  can help or backfire).
- **Risk threshold/safety parameters** — cut corners to save
  money/time vs. gold-plate. Directly echoes the O-ring/Challenger
  tension; failures under a cut-corner launch should feel earned.
- **Provisioning/duration** — longer missions cost more but unlock
  bigger objectives; ties directly to the Mars endgame.

## Launch Sequence (the "intense" management moment)
Turn-based-pressured (not real-time-twitchy), staged:
1. **Weather & site check** — site-specific weather personality
   (hurricane season, wind shear, swell height), rolling forecast with
   accuracy scaling with Intel investment. Temperature threshold is the
   explicit, inspectable Challenger-analog risk factor.
2. **Fueling window** — a countdown-style hold window (in sim-days, not
   real seconds); holding costs resources, scrubbing costs the fuel
   load and re-queues.
3. **Go/No-Go polls** — cycle through stations (Propulsion, Range
   Safety, Weather, Flight Surgeon, Payload), each attributed to a
   named desk/officer, showing **detailed real-time reasoning** so the
   player can use it to inform override-or-scrub. A no-go can be
   overridden; an override gone wrong should trace back to an
   under-invested stat.
4. **Launch or scrub** — the commit point, final computed risk locked
   in.
5. **Active mission** — launched missions run over several sim-days,
   not resolved instantly. Discrete in-flight events can fire
   (anomaly requiring a crew skill fix, closing weather window on
   return, life-support scare). Astronaut skills matter here as a
   live toolkit, not just an eligibility gate.
6. **Outcome & headlines** — resolves back into Sentiment via the two
   press outlets (see below).

A launch scrub for weather/temperature must always be available as a
zero-cost-except-time option — the player who pays attention can always
avoid the Challenger-analog outcome specifically.

## Tech Trees (Two Axes — both required together for "launch enablement")
- **Knowledge tech** (spent via R&D): **Propulsion**, split into
  **Chemical** (cheaper, well-understood risk, spine of early-mid game)
  and **Exotic** (nuclear-thermal/ion, required for a *sustained* Mars
  presence rather than flags-and-footprints; carries an inherent
  Sentiment tax regardless of real safety, and requires an advanced
  R&D Lab tier to unlock at all); **Life Support** (mission duration
  ceiling); **Materials Science** (cheaper/lighter/safer components);
  **Avionics/Computing** (forecast accuracy, Intel resolution).
- **Infrastructure tech** (spent via Funds+Materials+Labor, physical,
  site-specific): **Base-side** — Pad tier, VAB/assembly tier (gates
  vehicle size and Exotic-propulsion vehicles), Fueling depot tier
  (extends safe hold window), Crawler/transporter tier (rollout speed
  and weather resilience). **Center-side** — Mission Control tier
  (concurrent active missions, Go/No-Go and in-flight detail
  granularity), Training Center tier (astronaut skill caps/growth
  rate), R&D Lab tier (R&D generation rate; gates Exotic propulsion).

## Astronaut Corps
- **Last-names-only roster** (dossier/personnel-file tone; also avoids
  real-person overlap).
- **Capped active roster + larger Reserve Corps**; promotion from
  reserve to active is its own decision.
- **Recruiting pools** unlock over time with Sentiment/era — test
  pilots first, then scientist-astronauts, then (as history
  progresses) an expanding, more diverse recruiting pool, played with
  real narrative weight.
- **Six skills**: Piloting, Engineering, EVA, Science, Command, Public.
  Missions gate on skill thresholds and use skills live during
  in-flight events.
- **Aging out to Public Icon status** — a real choice at the trigger
  point: retire to full-time PR duty (locks in passive Sentiment,
  frees an active slot, astronaut safe forever) vs. one more flight
  (higher stakes because this is now the most-covered person aboard).
- Astronaut death is a real possible outcome (names are fictionalized,
  so this is fully permissible) — but historic disaster analogs
  (Apollo 1, Challenger) are **avoidable via player choice** (deeper
  research/inspection pre-launch, weather/temperature scrubs), not
  scripted to occur.

## Milestone Missions & Alt-History Forks
- **Pre-curated milestone missions** pace tech unlocks and double as
  tutorial beats.
- **Smaller unmanned missions** (research/commercial/military) are
  optional but strategically valuable — they bank Funds/R&D and prove
  out hardware reliability, lowering risk on the milestone attempt
  that follows.
- **Scripted alt-history fork points** are tied to milestones
  specifically.
- **Partnership/combined missions** with the rival program require a
  second axis of readiness beyond player stats: a Sentiment threshold
  AND favorable rival relations — the one milestone type that isn't
  purely a function of program quality.

## Rival Program(s)
Visible, reactive (not a scripted background timer) — scouted with
uncertainty inversely proportional to Intel investment; rival moves
react to player strategy. Scales across acts: one Cold War rival early,
a second rising program mid-game, then multiple leaner
private/commercial entrants late-game (mirrors the real shift toward
commercial spaceflight).

## Contractors
Generic company names that closely parody real aerospace companies.
Each has a specialty (propulsion, avionics, life support, structural)
and a loyalty meter — rises with repeat contracts, falls when a rival
bid is chosen; loyalty can pay off (unprompted lobbying assist) or bite
back (a leak to a hostile outlet) unpredictably. (Phase 3+)

## Press
Two named outlets, not individual journalist cards:
- **Daily Supporter** — always finds the positive spin, even on a
  scrub/failure.
- **Detractor Weekly** — always finds the skeptical angle, even on a
  clean success.
Each produces a headline/front page after every mission — the
narrative capstone of the launch sequence, feeding back into Sentiment.

## Administrations
Sentiment accumulates toward election-cycle checkpoints; crossing
thresholds grants a "mandate" the player can spend to weight the odds
toward a specific administration archetype (hawk/fiscal
conservative/idealist) rather than a random draw — leverage, not a
guarantee. Each archetype reshapes budget-cycle math and available
decision cards for its term. (Phase 3+)

## Endgame & Sequel Structure
Reaching the Mars milestone unlocks a choice of follow-on campaigns:
**Venus** (hostile-atmosphere/orbital science), **Io** (radiation/
volcanism extreme engineering, an Exotic-propulsion/Materials-science
showcase), **Asteroid Belt** (resource-economics as the primary
objective). Open question, not yet decided: single continuous save
across campaigns vs. New-Game+ per campaign with carried-over legacy
bonuses.

## Monetization
Hybrid model: **free first act**, then a **one-time purchase** unlocks
the full campaign. Ongoing IAP after that limited to **cosmetics and
timeline-slots** (running multiple concurrent alt-history saves) —
explicitly avoiding pay-to-win. Rewarded video ads may grant small,
non-core bonuses (e.g. a one-time Sentiment nudge or an early
intelligence peek), thematically framed as intel briefings.

## MVP Scope (build this first, nothing more)
- **One site** (Cape Canaveral is the presumed default).
- **Trimmed resource loop:** Sentiment + Budget + Materials only.
  No Intel, no Labor split — use a generic "crew readiness" stat.
- **Simplified 3-stage launch sequence:** weather check → go/no-go →
  outcome. (Full fueling-clock tension is Phase 2.)
- **A small hand-authored set of Mercury-era decision cards.**
- **One scripted milestone mission** as the vertical slice.
- **Both press outlets**, generating headlines after the milestone.
- **Flowing clock** with speed control (paused/normal/fast/faster),
  daily internal tick, hard-pause only on the go/no-go window.
- **Local-only saves.**
- No astronaut roster, no tech tree, no rivals, no contractors, no
  security threats, no status-menu UI yet.

## Phase 2
Full resource web (Intel, Technical/Operations Labor split), named
astronaut roster (active/reserve), knowledge tech tree, base/center
infrastructure tiers, site security, VIP tours, status-menu UI
(persistent flagged-items menu, badge counts, per-site severity),
cloud sync for saves, second site.

## Phase 3
Rival program(s) as a visible/reactive track, contractors with
loyalty, administrations and Sentiment-driven influence, scripted
alt-history forks, partnership missions.

## Sequel / Later
Post-Mars campaign branch (Venus/Io/Asteroid Belt), multiple rival
eras, additional sites where the choice is meaningfully different from
the first.

## Working Principles
- **Pattern discipline:** every system (resources, security, tours,
  launches) reduces to the same shape — a meter/resource, a decision
  card that spends or risks it, and an outcome that ripples back into
  Sentiment/Budget. New systems should be new cards on the existing
  skeleton, not new engine mechanics.
- **Simulation Core has zero UI dependencies** and should be built and
  tested independently of any screen.
- **Content is data**, not code — cards, tech nodes, and mission
  scripts live as JSON/TS objects so they can be authored without
  touching engine logic.
- **Ship the MVP loop before adding depth.** The backlog above is
  intentionally large; the MVP's job is to prove the core loop (decide
  → launch → risk → sentiment ripple → repeat) is fun before any of it
  gets built.
